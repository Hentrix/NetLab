# Мастерская образов NetLab (Debian 13)

## Назначение

Мастерская — рабочее место администратора, который один раз готовит систему, затем публикует самостоятельный базовый QCOW2 для дальнейшего использования в разных лабораториях. В каталоге шаблонов используется иерархия **категория → семейство → версия** (например, Серверы → Windows Server → 2022, Компьютеры → Windows → 10, Серверы → Debian → 13).

## Сценарий администратора

1. Откройте «Библиотека образов» или «Мастерская образов». Загрузите ISO установщика. Сервер проверяет ISO9660 и помещает его в `/var/lib/netlab/images/<id>.iso`. ISO не является загрузочным системным диском.
2. В «Мастерской образов» выберите ISO, категорию, семейство, версию, RAM/vCPU, модель NIC и размер будущего системного диска. Нажмите «Создать VM для установки». API выполняет создание диска, лаборатории и QEMU-узла одной операцией: при ошибке сохранения удаляются новые файлы и отменяются изменения состояния.
3. NetLab создаст отдельную лабораторию «Подготовка ...», **пустой QCOW2** и QEMU-узел с CD-ROM ISO. Запустите VM. В карточке устройства нажмите **«Экран (VNC)»**. Используйте мышь и клавиатуру внутри графического установщика. Раздел доступен в /next/.
4. Установите ОС на диск VM, установите драйверы, настройте SSH/RDP/guest tools, обновления, выполните желаемую очистку. Для тиражирования Windows выполните Sysprep/OOBE; для Linux удалите host SSH keys и сбросьте machine-id в рамках вашей политики, чтобы не дублировать идентификаторы. Не включайте персональные секреты и учётные данные в общий образ.
5. **Штатно выключите гостевую ОС** и убедитесь, что QEMU-узел остановлен. В «Мастерской» выберите подготовленную VM: название, семейство и версия подставляются из её чернового диска, но их необходимо проверить. Перед публикацией сервер выполняет `qemu-img check -f qcow2` рабочего overlay, затем `qemu-img convert -f qcow2 -O qcow2` в отдельный файл, проверяет и его. При ошибке проверки образ не публикуется; исходная лаборатория и диск сохраняются.
6. После публикации готовый вариант появится в общем списке шаблонов; при создании устройства пользователь выбирает, например, «Windows Server 2022». Для каждого устройства NetLab использует **собственный overlay** поверх опубликованного базового диска. Важно: последующие изменения в опубликованном базовом образе не должны менять уже созданные overlay; вместо этого публикуйте новую версию.

## Загрузочный носитель после установки

После установки ОС в разделе **«Опубликовать установленную ОС»** выберите подготовительную VM и убедитесь, что она **остановлена**. Доступны действия «Загрузка с диска», «Загрузка с ISO», «Извлечь ISO» и «Подключить выбранный ISO».

- **Загрузка с диска:** ISO остаётся подключённым, но QEMU сначала пробует системный диск (порядок `cd`).
- **Загрузка с ISO:** QEMU сначала пробует установочный CD-ROM (порядок `dc`).
- **Извлечь ISO:** удаляется только ссылка на установочный носитель в конфигурации VM. Сам ISO на сервере и системный QCOW2 остаются неизменными.
- **Подключить выбранный ISO:** в качестве CD-ROM подключается ISO, выбранный в первом шаге мастерской, без изменения системного диска.

Все изменения вступают в силу при следующем запуске QEMU. Для старых VM с ISO и незаданным приоритетом сохранено прежнее поведение: загрузка с CD-ROM первой. Если ISO нет, QEMU загружает системный диск. Сервер не разрешает менять носитель, пока запущено хотя бы одно устройство лаборатории, и откатывает конфигурацию при ошибке сохранения.

`PATCH /api/labs/<lab>/nodes/<node>/media` принимает JSON `{"installISOId":"<id или пустая строка>","bootOrder":"disk"}`. Допустимые значения `bootOrder`: `disk`, `cdrom`.

## Ревизия из уже подготовленной системы

Для обновлений ОС и установки дополнительного ПО не нужно повторно загружать ISO или переустанавливать систему:

1. В «Мастерской образов» в каталоге готовых систем нажмите **«Создать новую версию»** или выберите исходный опубликованный шаблон в форме ревизий.
2. Укажите название будущей подготовительной VM и **новую версию**, отличающуюся от существующих для того же семейства и категории.
3. Нажмите **«Создать ревизию»**. API `POST /api/workshop/revise` проверит исходный шаблон и создаст **независимую копию** опубликованного QCOW2 через `qemu-img convert`, отметит копию как черновик, создаст отдельную лабораторию и QEMU-узел. Исходный опубликованный файл не изменяется, а новая копия не зависит от него через backing-файл.
4. Запустите VM в лаборатории, выполните обновления и настройки, затем **штатно выключите гостевую ОС**.
5. Вернитесь в мастерскую и опубликуйте подготовленный образ под новой версией. Старые лаборатории продолжат использовать исходную базу.

Для создания ревизии требуется свободное место на диске под её копию. API сохраняет лабораторию и метаданные черновика одной транзакцией состояния; при ошибке сохранения удаляет созданный QCOW2 и откатывает записи. Не публикуйте версии с паролями, токенами и персональными ключами внутри гостевой ОС.

## Конфигурация и защита

В настройках QEMU для остановленной лаборатории можно менять ISO и приоритет загрузки. Системный диск выбирается отдельно: ISO не предлагается в списке системных дисков. По умолчанию сохраняется SeaBIOS; поддержка UEFI/OVMF и TPM не включена в план. Для стандартных QCOW2 QEMU использует `cache=none,aio=threads`; реальная скорость зависит от накопителя и наличия KVM.



- **QEMU ISO / VNC:** нет открытых наружу TCP-портов 5900/5700. QEMU слушает локальные UNIX-сокеты внутри `/var/lib/netlab/runtime/<lab>/<node>/`.
- **noVNC:** установщик Debian 13 ставит официальный пакет `novnc` из репозитория системы; Go API отдаёт статику по `/novnc/`. Трафик QEMU идёт через защищённый одноразовым WebSocket-билетом прокси `/vnc/<ticket>`, билет выдаётся только после авторизации административным токеном и действует до 30 секунд для открытия соединения. При HTTPS браузер использует WSS.
- **Использование ресурсов:** ISO и базовые QCOW2 хранятся отдельно; узлы работают на своих overlay. Публикация временно сериализует операции API с лабораториями, чтобы не читать диск во время записи.
- **Восстановление после сбоя NetLab:** при старте службы NetLab сверяет TAP и OVS с сохранёнными лабораториями. Если старый QEMU продолжает отвечать через локальный QMP-сокет, автоматическая очистка сети этой лаборатории отменяется, а раздел «Состояние системы» показывает ошибку для ручной диагностики. Если старый процесс отсутствует, удаляются только оставшиеся сетевые ресурсы; `disk.qcow2`, установленные ОС, ISO и журналы сохраняются. Восстановление не подхватывает автоматически чужие процессы QEMU и не гарантирует отсутствие старого VPCS без проверки хоста; не запускайте два экземпляра API на одном хранилище.
- **Диагностика запуска узлов:** ошибки `startNode`, возникшие до старта дочернего QEMU/VPCS, сохраняются в памяти NetLab и доступны в поле `error` устройства через API до следующей успешной попытки или перезапуска службы. В редакторе проблемные устройства выделяются маркером и перечисляются над топологией. Кнопка «Повторить ошибки» пытается запустить только остановленные узлы с ошибками, не затрагивая исправные работающие VM. Для дополнительной диагностики используйте «Журнал устройства». Ошибки запуска не сохраняются между перезапусками самого API.
- **Запуск лаборатории целиком:** перед запуском всех устройств NetLab проверяет наличие базовых дисков, установочных ISO и отсутствие незавершённой очистки TAP. Если один узел не стартует, система останавливает только VM, запущенные текущей командой, и сообщает об ошибках отката. Уже работавшие устройства не останавливаются. Для детальной диагностики смотрите журналы отдельных VM в редакторе. Успешная проверка ссылок на образы не гарантирует запуск QEMU, поэтому ошибки исполнения по-прежнему обрабатываются при старте.
- **Завершение VM:** состояние «остановлена» не означает, что TAP и ресурсы уже очищены. Пока процесс завершает очистку, NetLab запрещает изменение или удаление лаборатории и повторное использование узла. Команда остановки сообщает об ошибке, если завершение не подтверждено; OVS-мосты не удаляются при неуспешной остановке VM. Это защищает рабочие QCOW2 от удаления при ещё активном дочернем процессе.
- **Повторный запуск VM:** рабочий `runtime/<lab>/<node>/disk.qcow2` создаётся через временный файл и становится рабочим только после успешного `qemu-img create`, проверки формата и ссылки на ожидаемый базовый диск. При повторном запуске существующий overlay не пересоздаётся; ссылка на базовый образ проверяется, чтобы не запустить VM с чужим диском. Изменения внутри гостевой ОС сохраняются в overlay конкретного устройства, а опубликованный базовый шаблон остаётся общим и неизменным. Сбой создания не должен оставлять повреждённый `disk.qcow2`; оставшийся `.creating` безопасно удаляется при следующей попытке.

- **Сейчас нет пользовательских ролей:** NetLab до этого этапа использует **один административный токен**. Не сообщайте его студентам. Для эксплуатации 20 человек необходимы отдельные аккаунты, RBAC, владелец/ACL лабораторий, квоты на CPU/RAM/disk, ограничение одновременных VM, аудит операций и массовое удаление неиспользуемых overlay.
- **Ограничения оборудования:** проект использует BIOS (pc/SeaBIOS) и адаптеры ide/virtio/scsi. UEFI/OVMF, TPM и Secure Boot не планируются. ОС, которым они обязательны, не входят в поддерживаемый сценарий установки.
- **Эксплуатационные проверки:** после установки на Debian проверьте загрузку ISO, установку конкретной ОС в VNC, ввод клавиатуры, публикацию, самостоятельность qcow2, запуск двух устройств из одного шаблона, сетевые интерфейсы и отсутствие доступа к VNC без билета. CI тестирует код и заглушки API, но не заменяет загрузку реального гостя.

## API мастерской

```text
POST /api/images                        multipart/form-data, file=.iso/.qcow2/.raw
POST /api/images/blank                  {"name":"…","sizeGiB":64}
PATCH /api/images/<id>                  {"name":"…","category":"server","family":"Windows Server","version":"2022"}
POST /api/labs/<lab>/nodes              обычная модель QEMU + "installISOId":"<iso-id>"
POST /api/workshop/prepare              {"name":"Debian 13","isoId":"…","category":"server","family":"Debian","version":"13","sizeGiB":32,"ram":2048,"cpus":2,"nicModel":"e1000"}
POST /api/workshop/revise               {"imageId":"…","name":"Debian 13.1","version":"13.1"}
POST /api/workshop/publish              {"labId":"…","nodeId":"…","name":"…","category":"server","family":"Windows Server","version":"2022"}
GET  /api/templates                     базовые профили + опубликованные версии
POST /api/labs/<lab>/nodes/<node>/vnc-ticket
GET  /vnc/<одноразовый-билет>           WebSocket upgrade, только с того же origin
```

Административный токен остаётся только в заголовке `Authorization` запросов `/api/`; в WebSocket URL передаётся одноразовый билет. Лимит загрузки: 16 ГиБ; размер создаваемого виртуального диска: 4–512 ГиБ (выделяется разреженно).

## Приёмка и совместимость

Старый редактор `/` пока доступен; мастерская образов и графическая консоль добавлены в новый `/next/`. Сохранённые ранее QCOW2/RAW не меняются и считаются дисковыми образами, даже если у записи отсутствует новое поле `kind`. В проекте по-прежнему требуется фактическая проверка на Debian 13 / Proxmox с nested virtualization.
