# Ethernet-кабели NetLab v0.6.8

## Создание соединения мышью

1. Откройте лабораторию и наведите курсор на иконку устройства.
2. В верхнем правом углу значка появится круглая кнопка со звеньями цепи.
3. Зажмите левую кнопку мыши на значке и ведите линию к другому устройству.
4. Когда целевой узел подсветится зелёным, отпустите кнопку.
5. Выберите **два свободных порта**, подтвердите добавление. Один порт не может одновременно занимать два кабеля.

Быстрое нажатие на значок (без перетаскивания) включает режим выбора второго устройства кликом. Кнопка «Кабель» в панели также остаётся доступной. Нажатие `Esc` отменяет протягивание. Двойной клик по существующему кабелю открывает диалог переназначения, ПКМ по нему — контекстное меню с удалением. Удаление/переназначение разрывают реальный трафик по соответствующему соединению.

## Обозначения интерфейсов

Подписываются **оба конца** линии: `ether1`, `Gi0/0`, `e0/0`, `GE0/0/0`, `Fa0/0`, `ge-0/0/0`, `eth0`, `ens3`. Редактор размещает их возле иконок, по направлению к другому устройству. Две и более линии между одними устройствами разводятся небольшими параллельными смещениями.

Названия определяются автоматически для некоторых семейств или задаются при создании устройства. Нажмите **ПКМ по устройству → Обозначения интерфейсов**, чтобы изменить формат подписей без остановки VM. Это **только подписи в редакторе**; фактическая нумерация внутри гостевой ОС зависит от образа, модели NIC и порядка PCI-устройств. Проверяйте `show interfaces`, `/interface print`, `ip link` и похожие команды внутри гостевой ОС.

## Геометрия и оформление кабелей

NetLab выбирает ближайшую сторону значка для направления на соседнее устройство. Каждая сторона выделяет собственные точки присоединения для всех интерфейсов, поэтому кабели к разным соседям не должны выходить из одной точки. Для нескольких параллельных соединений сохраняется отдельный слот каждого кабеля. При перемещении устройств геометрия пересчитывается автоматически.

Подписи интерфейсов располагаются около их конечных точек. При возможных пересечениях с устройствами или другими подписями редактор старается сдвинуть их вдоль линии или в сторону. На сильно перегруженном полотне оптимальное решение может быть недостижимо — переместите узлы, чтобы освободить пространство.

**ПКМ по линии → «Оформление кабеля»** позволяет задать её цвет, толщину и тип (сплошная, пунктирная, точечная). Настройки хранятся отдельно от сетевых параметров и применяются в PNG-экспорте. Не следует трактовать цвет линии как подтверждение IP-связности.

## Подключение на горячую

При запуске QEMU NetLab создаёт выбранное количество NIC и TAP, но оставляет отсутствующие в топологии кабели с `carrier down` через QMP `set_link`. Добавление кабеля во время работы VM создаёт отдельный изолированный OVS bridge, присоединяет два TAP и устанавливает `carrier up`, **когда оба устройства запущены**. Если работает только одна VM, интерфейс остаётся в состоянии ожидания и поднимается после запуска второго устройства. Удаление кабеля отключает carrier и очищает OVS. При ошибках backend старается откатить незавершённую транзакцию, прежде чем подтвердить изменение топологии.

Это **hot wiring / hot connection**, а не PCI hotplug нового сетевого адаптера. Изменение количества NIC требует остановки VM. Для этой версии реализован только QEMU x86_64; механизмы Dynamips/IOL/VPCS ещё не подключены.

Состояние `Активно` означает успешную коммутацию двух работающих VM в NetLab, **не** гарантирует прохождение IP-трафика или правильность конфигурации внутри гостевых ОС.

## Как проверить на Debian 13

```bash
sudo systemctl status netlab
sudo ovs-vsctl show
sudo journalctl -u netlab -n 100 --no-pager
```

1. Запустите две VM с установленными NIC; соедините, не останавливая.
2. Убедитесь, что статус кабеля стал «Активно» и соответствующий интерфейс появился в гостевой ОС.
3. Выполните ping между назначенными IP или проверку L2 (ARP) внутри VM.
4. Удалите соединение — carrier должен отключиться, L2 перестать проходить.
5. Подключите другой свободный порт, не перезапуская VM.

Автотесты (`go test ./...`) используют фиктивные QMP-сокеты и имитируют команды OVS. В Chromium протестированы действия мышью, диалог портов и отображение подписей с тестовым API. **Реальный сетевой обмен между двумя QEMU-гостями на целевой Debian 13 ещё не проверялся в этом окружении.**
