# NetLab v0.6.4 — подписи устройств и массовое добавление

NetLab — сетевой эмулятор для Debian 13 Trixie. В основе — QEMU/KVM, Open vSwitch, Go API и браузерный редактор топологии.

> Это MVP. Dynamips, Cisco IOL/IOU, VPCS и контейнерные движки пока не реализованы; фактический запуск конкретных сетевых образов нужно проверять на целевом Debian.

## Что нового

- Убрана непрозрачная белая подложка под названиями устройств при наведении и выделении. Текст остаётся контрастным на светлом полотне.
- В окне «Добавление устройства» появилось числовое поле **«Количество устройств»** от 1 до 32, по умолчанию **1**.
- При количестве больше одного вызывается API `POST /api/labs/{labId}/nodes/batch`: все экземпляры создаются одной транзакционной операцией с суффиксами `1`, `2`, … без конфликтов с именами уже существующих узлов, и располагаются сеткой (до пяти в строке). Например, три экземпляра `MikroTik CHR` станут `MikroTik CHR 1`, `MikroTik CHR 2`, `MikroTik CHR 3`.
- Пакетное создание только создаёт узлы, **не запускает виртуальные машины**. Количество создаваемых NIC у каждого экземпляра остаётся параметром «Ethernet-порты», независимым от количества устройств.
- Сохранены снимок PNG всей топологии и единая нижняя строка состояния из v0.6.3.

## Обновление существующей установки

Эта версия изменяет **и веб-интерфейс, и Go API**. Поэтому обновления только `web/` недостаточно. На Debian 13 предварительно сохраните данные:

```bash
sudo tar -C / -czf /root/netlab-backup.tar.gz etc/netlab var/lib/netlab
```

Из распакованного каталога проекта:

```bash
sudo bash scripts/install-debian13.sh
```

Сервис будет перезапущен, затем обновите страницу браузера через `Ctrl + F5`. Установщик не удаляет `/var/lib/netlab` и `/etc/netlab/netlab.env`.

## Проверки

Выполнялись `go test ./...`, `go vet ./...` и `node --test tests/*.test.mjs`. Проверены пакетное добавление, уникальность названий, сохранение и отказ некорректных запросов. Полное браузерное взаимодействие на тестовом сервере заблокировано политикой Chromium в среде разработки и требует проверки на целевой системе.

## Функции редактора из v0.6.3

- Все показатели состояния теперь в **одной горизонтальной строке**: подключение к серверу, CPU, RAM, число устройств, число соединений, задержка HTTP API и время последнего сохранения. На узком экране строка прокручивается вбок, а не переносится на второй ряд.
- Внутри существующей лаборатории кнопка «Новая лаборатория» в заголовке скрыта. Создание лаборатории остаётся в боковом меню и на пустом экране.
- Кнопки в заголовке: **Запустить всё → Остановить → Снимок → ⋯**. Кнопка `⋯` находится последней, слово «Лаборатория» из её подписи убрано; удаление по-прежнему требует подтверждения.
- **Снимок** — это PNG-файл **всей сетевой топологии**, а не снимок виртуальной машины: устройства, PNG-значки, кабели, их состояния, подписи портов, текст и примечания. В изображение не включаются боковые панели, инструменты и курсор. Текущее положение камеры/масштаб не обрезают экспорт. Скачивание начинается сразу после подготовки файла в браузере. Именование: `NetLab_<имя>_YYYY-MM-DD.png`.
- Изменения только в `web/`: установленный backend и системные настройки менять не требуется.

## Быстрое обновление с v0.6.2 (только web)

Из распакованного каталога `netlab-v0.6.3` на сервере:

```bash
sudo cp -a web/. /opt/netlab/web/
```

Затем обновите страницу через `Ctrl + F5`. Файлы `/var/lib/netlab`, библиотека образов и токен не изменяются.

**Ограничения:** PNG-экспорт — не резервная копия лаборатории, а изображение текущей модели. Фактическая чёткость значков ограничена разрешением исходных PNG. При очень больших топологиях экспорт ограничивает размер Canvas, чтобы не расходовать всю память браузера. Реальную загрузку образов и обмен пакетов в этой версии не проверяли.

## Что реализовано

- Go HTTP API и токен-аутентификация, локальное прослушивание `127.0.0.1` по умолчанию.
- Рабочее полотно с PNG-иконками из пользовательского архива (550 изображений), плавающей панелью инструментов и отдельной панелью текущих устройств слева от полотна; группировка маршрутизаторов, коммутаторов, безопасности и конечных узлов, поиск, выделение на схеме и перенос расположения узла из списка.
- Два вида аннотаций (текст и примечание), восемь маркеров изменения размера, изменение цвета текста, заливки, рамки, шрифта и выравнивания; все настройки сохраняются в JSON лаборатории и валидируются backend. В v0.6.2 минимальная геометрия изменена (примечание — от 144×58, текст — от 96×36), при сжатии текст автоматически уменьшается до 11 px только визуально (основной размер шрифта не переписывается); переполнение длинного текста доступно через внутреннюю прокрутку без масштабирования полотна. В контекстное меню добавлено «Подогнать высоту под текст», поля цвета в диалоге размещены непосредственно рядом с подписями.
- Системная строка состояния под полотном: фактические CPU/RAM Debian, задержка HTTP API и время последнего сохранения state.json. API телеметрии требует административный токен. Первая выборка CPU после старта обозначается «—», пока нет двух последовательных срезов /proc/stat.
- Режим «Рука» блокирует любые действия с устройствами, кабелями и аннотациями непосредственно на полотне. Колесо масштаба и перетаскивание фона продолжают работать.
- Создание/удаление лабораторий; перемещение устройств по полотну; панорамирование средней кнопкой мыши, пробелом или инструментом «Рука»; масштабирование колёсиком относительно курсора; подгонка топологии под экран; сохранение координат.
- Загрузка локальных автономных дисков **QCOW2** и **RAW** с определением формата через `qemu-img info`.
- Создание qcow2 Copy-on-Write overlays при первом запуске узла.
- Запуск/остановка QEMU, управление через локальный QMP сокет.
- Перенаправление serial console в браузер (поллинг). Только если guest действительно выводит serial console.
- Изолированные L2 соединения через `Open vSwitch + TAP` (одна отдельная bridge на каждую связь).
- Один физический Debian 13 или Debian VM с доступным nested KVM; при отсутствии KVM включается медленный TCG.
- Запуск QEMU от непривилегированного пользователя `netlab-vm`.
- systemd unit, установщик на Debian 13, минимальные тесты.

## Установка на чистый Debian 13

Под root/sudo **из распакованного каталога с исходниками**:

```bash
sudo bash scripts/install-debian13.sh
```

Скрипт установит QEMU, Open vSwitch, Go, создаст сервисную учётную запись `netlab-vm`, соберёт Go backend и запустит сервис. **Он не меняет физические сетевые интерфейсы, маршруты, DNS и firewall.**

```bash
sudo systemctl status netlab
sudo journalctl -u netlab -f
sudo bash scripts/check-host.sh
sudo bash scripts/diagnose-qemu.sh
sudo cat /etc/netlab/netlab.env
```

В браузере на сервере: `http://127.0.0.1:8080`.

На другом компьютере откройте SSH-туннель (на локальной рабочей машине):

```bash
ssh -L 8080:127.0.0.1:8080 user@IP_СЕРВЕРА
```

Затем откройте локально `http://127.0.0.1:8080` и вставьте значение **NETLAB_ADMIN_TOKEN** из `/etc/netlab/netlab.env`.

**Важно:** не проксируйте сервис наружу без TLS, дополнительной аутентификации, ограничений доступа и проверки безопасности. Backend выполняет привилегированные сетевые операции, рассчитан на доверенного администратора, multi-user security пока нет.

## Первый лабораторный запуск

1. Раздел **Образы**: загрузите свой лицензированный образ MikroTik CHR QCOW2 либо автономный Linux QCOW2/RAW.
2. Создайте лабораторию, выберите шаблон **MikroTik CHR** либо **Generic x86 QEMU**.
3. Создайте второй узел; наведите курсор на первый, зажмите значок соединения справа сверху и протяните его на второй. Выберите свободные порты (например, ether1 ↔ Gi0/0). Можно использовать и кнопку **Кабель** в панели инструментов.
4. Нажмите **Запустить всё**. TAP-интерфейсы создаются заранее для всех настроенных NIC; связи создают изолированные OVS bridges. Допускается добавлять, удалять и переназначать кабели после запуска обеих VM.
5. Дважды щёлкните на запущенном узле или нажмите **Консоль** в панели справа. Если образ не выводит serial console, используйте `qemu.log` для диагностики; графическая консоль пока не реализована.

Действия редактора: ПКМ по устройству открывает контекстное меню (старт/стоп, консоль, переименование, значок, параметры, кабель, удаление); ПКМ по кабелю позволяет удалить связь; двойной клик по пустому полю создаёт устройство; шаблоны выбираются в диалоге «Добавить устройство»; отдельное окно позволяет выбрать значок среди 550 PNG-файлов. Перемещение, изменение подписи и иконки сохраняются даже при работающем узле. Добавление, удаление и переназначение Ethernet-кабелей доступны при запущенных QEMU-устройствах (TAP + OVS + QMP carrier). Число виртуальных NIC и параметры VM требуют остановки. Наведи курсор на устройство, зажми значок кабеля справа сверху и протяни к другому устройству. Дальше выбери оба свободных интерфейса. Нажатие на значок без протягивания включает режим выбора второго устройства. В ПКМ и вкладке «Интерфейсы» есть настройка названий и скоростей для каждого отдельного порта, в том числе при запущенной VM. Форматы подбираются из семейства ОС и номинальной скорости (Cisco Fa/Gi/Te, Huawei FE/GE/10GE, RouterOS ether и другие). Эти метаданные не меняют фактическую модель или negotiated speed сетевой карты QEMU.

Ограничения: максимум 16 подключённых интерфейсов на узел; схема x86_64, pc/SeaBIOS; Каждая VM заранее получает настроенное число NIC, даже если кабели пока не подключены; настройка интерфейсов внутри гостевой ОС выполняется вручную. Соединения можно менять при работающих QEMU-узлах; гостевая ОС может реагировать на carrier с задержкой. Изменения не создают новые PCI-устройства на горячую. Имена/профили QEMU пока ограничены разрешёнными параметрами.

При удалении лаборатории удаляются её overlay-диски. Изменение образа существующего узла **не удаляет** его overlay, поэтому смена образа на том же узле не поддерживается как корректная операция: удалите узел и создайте новый. Не используйте этот MVP для хранения ценных конфигураций без отдельных резервных копий `/var/lib/netlab`.

## Разработка без установки

На Linux (Go >= 1.23):

```bash
cd netlab-v0.6.1
go test ./...
NETLAB_ADMIN_TOKEN="$(openssl rand -hex 32)" go run ./cmd/netlab -data ./data -web ./web
```

Для **реального запуска QEMU** требуются Linux, Open vSwitch, iproute2, привилегии на управление TAP/OVS и системный пользователь `netlab-vm`; для проверки UI, API и тестов без QEMU это не нужно. Go-модули с внешними зависимостями не требуются.

## Хранилище данных

```text
/var/lib/netlab/
├── state.json               # atomic JSON state, mode 0600
├── images/<id>.<format>     # импортированные base images
└── runtime/<lab>/<node>/
    ├── disk.qcow2           # writable overlay
    ├── qemu.log
    ├── monitor.sock         # QMP
    └── serial.sock          # serial console
```

В будущих релизах JSON persistence будет заменена на PostgreSQL с миграциями; API и модель домена позволяют это сделать без смены формата топологии.

## Обновление ранее установленной версии (включая v0.4.0)

Архив v0.6.1 распакуйте в отдельный каталог (не в `/opt/netlab`) и повторите:

```bash
sudo bash scripts/install-debian13.sh
sudo systemctl restart netlab
```

Установщик сохраняет `/etc/netlab/netlab.env` и `/var/lib/netlab` (библиотеку образов и лаборатории), но перед обновлением рекомендуется сделать резервную копию:

```bash
sudo tar -C / -czf /root/netlab-data-backup.tar.gz etc/netlab var/lib/netlab
```

После обновления обновите веб-страницу с очисткой кеша (`Ctrl+F5`). Исправление v0.2.1 добавляет `AmbientCapabilities=CAP_SETUID` в systemd unit. На диагностированном сервере `CapEff` не содержал CAP_SETUID, хотя сервис работал от root: это мешало Go выполнить `syscall.Credential` при запуске QEMU от `netlab-vm`. После обновления запустите `sudo bash /opt/netlab/scripts/diagnose-qemu.sh` и проверьте `CAP_SETUID (effective): yes`, затем повторите запуск узла. Другие ошибки QEMU требуют отдельной диагностики. `NoNewPrivileges=true` сохранён. Фактический запуск образов на целевом Debian ещё не проверен.

## Каталог иконок

Архив `icons.tar.gz`, предоставленный пользователем, по факту был **обычным TAR** (не gzip). Мы проверили и извлекли 550 PNG-файлов без переименования в `web/icons/`; `web/icons.json` — перечень доступных иконок для окна выбора. В лабораториях сохраняется только поле `icon`, у старых узлов подбирается значок по типу/названию, поэтому миграция `state.json` не требуется. Изображения влияют только на внешний вид, а не на исполняемый профиль VM. **Права на дальнейшее распространение изображений должны проверяться владельцем проекта**, поскольку архив не сопровождался явной лицензией.

## Security / юридические замечания

Мы не распространяем проприетарные Cisco/Huawei/Fortinet-образы, лицензии и keygen. Используйте только образы, право использования которых у вас есть. Отсутствие гипервизора Proxmox *не исключает* необходимость аппаратной виртуализации CPU — для KVM на bare metal или nested virtualization внутри VM.

Если API с правами root будет атакован, сервер может быть скомпрометирован. Текущий локальный сервис с токеном — не полноценная многопользовательская защищённая платформа. Для публикации в интернет нужен отдельный hardening-аудит.

## Редактор v0.6.1

Новая компактная панель инструментов находится **в левом верхнем углу самого полотна**:

- **Выбор (V):** выбор одного устройства; Ctrl/Shift + клик для нескольких, одновременное перемещение выбранных узлов.
- **Рука (H/Space):** панорамирование; колесо мыши — масштабирование относительно курсора.
- **Кабель (C):** соединение устройств; также есть значок соединения при наведении на узел.
- **Рамка (M):** выделение группы устройств прямоугольником.
- **Текст (T):** щёлкнуть на свободном месте, ввести текст, сохранить аннотацию.
- **Примечание (N):** протянуть прямоугольник и написать заметку. Оба вида аннотаций сохраняются в лаборатории.
- **«+»:** выбор шаблона и добавление устройства.

Панель справа не содержит каталога; в ней есть вкладки **Обзор** (образ, ресурсы, запуск, консоль) и **Интерфейсы** (имя порта, номинальная скорость, сосед и действие). Удаление лаборатории — в меню «⋯ Лаборатория» в заголовке. Для кабелей между одинаковой парой узлов используются разные геометрические слоты на гранях иконок, чтобы параллельные линии не совпадали.

Метаданные `nodes[].ports[]` и `labs[].annotations[]` добавлены как необязательные поля JSON. Старые лаборатории открываются без миграции; удалять `state.json` **не нужно**. Дополнительная инструкция: `docs/EDITOR.md`.

Проверка логики без QEMU: `go test ./... && go vet ./... && node --test tests/*.test.mjs`. Реальный KVM/OVS/гостевые ОС необходимо проверять на целевом Debian. В этой сборке визуальное тестирование в браузере с настоящим backend не пройдено, поскольку Chromium тестовой среды запрещает доступ к loopback; HTTP API и отдача статических файлов проверены отдельно.


## Обновления интерфейса v0.6.1

- Слева от рабочей области появилась **панель узлов текущей лаборатории** (не каталог QEMU-шаблонов): группы по типу, фильтр, статус, имя образа. Щелчок выделяет и центрирует узел, drag & drop на полотно переносит его позицию. Добавление нового узла доступно кнопкой `＋`.
- Под полотном вместо текста-подсказки — две строки с телеметрией: подключение, CPU, использованная/полная RAM, число узлов и связей, задержка HTTP API и последнее сохранение.
- `Рука` и удержание `Space`: все интерактивные объекты на полотне блокируются CSS pointer-events, а свободная область используется только для панорамирования. Клики по узлам, открытие консоли, соединения и редактирование примечаний на полотне не выполняются.
- Клик по примечанию выбирает его; наведение отображает маркеры на всех сторонах и углах. Перетаскивание маркера меняет размеры с учётом масштаба; двойной клик открывает оформление. Цвета (hex), заливка или прозрачность, граница 0–4 px, шрифт 9–72 px, жирный/курсив/подчёркивание, выравнивание доступны как тексту, так и примечанию. Изменения вносятся без остановки VM. Старые заметки получают прежние цвета по умолчанию.

**Статус тестирования:** `go test`, `go vet`, `node --test tests/*.test.mjs`, HTTP smoke и браузерная проверка интерфейса в тестовом Chromium через изолированный макет API. Проверка настоящего QEMU и сетей OVS на хосте Debian 13 в этом окружении не выполнялась.


## Чёткость текста и иконок (v0.6.1)

Полотно больше не масштабируется через compositor `transform: scale()`; вместо этого CSS `zoom` применяется к содержимому отдельно от перемещения рабочего поля. Текст имён узлов и подписи интерфейсов пересчитываются браузером на каждом уровне масштаба. Перемещение полотна выравнивается по физическим пикселям экрана.

Иконки — исходные PNG из набора пользователя: некоторые имеют размер 42–64 px и при сильном увеличении не могут стать детальнее. Для максимальной чёткости используйте масштаб 100% либо замените иконки на PNG большего разрешения. Если текст размывается во всех частях интерфейса, проверьте масштаб браузера (`Ctrl+0`) и настройки масштабирования Windows.

## Исправление отрисовки и панели свойств v0.6.1

- Шрифты на полотне перерисовываются через CSS `zoom` вместо CSS compositor `scale`; округление pan-координат по физическим пикселям уменьшает размытие. Исходные PNG-иконки низкого разрешения остаются ограничением качества.
- Кнопка подключения над правым верхним углом устройства имеет постоянные размеры 28×28 px, не изменяется при наведении и соответствует сине-серой цветовой палитре NetLab.
- Заголовок правой панели статичен: «СВОЙСТВА УСТРОЙСТВА». Под именем устройства теперь указан его актуальный статус («● Запущен» / «● Остановлен» / «● Ошибка») вместо повторения названия образа; образ по-прежнему находится в разделе «Конфигурация». Дублирование статуса в заголовке убрано.
- Добавлены Node.js-тесты для отображаемых состояний, структуры панели и оформления кнопки.

Движок QEMU, существующие кабели и сохранённые лаборатории этими UI-изменениями не затрагиваются. Chromium в текущей тестовой среде заблокировал обращение к локальному HTTP-серверу (`ERR_BLOCKED_BY_ADMINISTRATOR`), поэтому полноценная визуальная проверка этой сборки в браузере на Debian пока не подтверждена.
