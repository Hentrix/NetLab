# Архитектура веб-интерфейса NetLab

## Цель

Постепенно перевести старый монолит `web/app.js` на Vue 3 + TypeScript, **без
замены Go API**, удаления лабораторий или изменения формата дисковых образов.

Два интерфейса работают с одним хранилищем:

- `/` — полный существующий редактор, пока основной;
- `/next/` — новая Vue-реализация, экспериментальная до достижения функционального паритета.

Разработчик должен **сначала собрать** `frontend` (с Node.js >= 20.19 и npm):

```bash
bash scripts/build-frontend.sh && sudo bash scripts/install-debian13.sh
# сначала проверит TypeScript/Vite, затем установит web/next/
```

Node.js и npm не нужны при штатной работе NetLab. Go отдаёт уже собранные
статические файлы с того же домена, что и `/api` и `/icons`. Внешние CDN
не используются. На сервере за reverse proxy это убирает необходимость в
CORS и стороннем доступе к JavaScript.

## Пакеты

| Пакет | Назначение |
|---|---|
| `vue` | Компоненты и реактивность |
| `pinia` | Единое состояние лабораторий, узлов и авторизации |
| `@vue-flow/core`, `@vue-flow/background` | Полотно, рёбра, соединение, трансформации |
| `@xterm/xterm`, `@xterm/addon-fit` | Долгоживущие терминалы CLI с вводом и ANSI |
| `@lucide/vue` | Единая библиотека SVG-иконок |
| `vite`, `@vitejs/plugin-vue`, `vue-tsc` | Сборка, типизация и разработка |

## Структура

- `src/stores/netlab.ts` — централизованная модель состояния и операции API;
- `src/api/client.ts` — типизированный HTTP-клиент и чистые доменные функции;
- `src/components/TopologyCanvas.vue` — редактор Vue Flow, действия кабеля;
- `src/components/DeviceNode.vue` — отображение устройств и source/target handles;
- `src/components/CableEdge.vue` — оформление линий и бейджи интерфейсов;
- `src/components/TerminalDock.vue` — вкладки xterm.js и SSE-подключение к backend;
- `src/App.vue` — временная оболочка. По мере миграции разбиваем на компоненты.

## Правила дальнейшего развития

1. **Не добавлять новую бизнес-логику в `web/app.js`.** Новые функции делать
   в Vue-компонентах и Pinia, существующие переносить по одной группе.
2. Не вводить новый API для тех же данных без необходимости. QEMU, VPCS и
   OVS обслуживаются Go, а не Node.js.
3. После миграции действия тестируются и в Go API, и во Vue Flow. Сетевая
   коммутация не должна зависеть от наличия терминала в браузере.
4. Метки портов, точки кабелей и состояния интерфейсов должны храниться
   в одной типизированной модели. Учитывать горячее подключение.
5. Не заменять функциональный редактор `/`, пока `/next/` не поддержит
   полностью аннотации, массовые действия, настройку портов, редактирование
   кабелей, PNG-снимки, библиотеку образов и совместимость лабораторий.
6. Токен не включается в bundle и не записывается в `localStorage`.
   API вызывается только same-origin через HTTPS reverse proxy.

## Проверка

На машине, где доступен npm:

```bash
cd frontend
npm install
npm run typecheck
npm run build
npm run test
```

Дополнительно проверять UI в реальном Chromium и работу VPCS/QEMU на Debian 13.
Проверка чистого TypeScript синтаксиса **не заменяет** `vue-tsc`, `vite build`
или браузерный тест.


## Аннотации Vue
В редакторе `/next/` доступны текстовые метки и примечания: создание на панели инструментов,
перемещение мышью, двойной клик для редактирования текста и оформления, удаление.
Данные хранятся в общем `labs/{id}/annotations` API, совместимом со старым интерфейсом.
